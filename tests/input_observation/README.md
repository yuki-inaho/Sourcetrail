# 入力変更・位置・不整合出力の人工対象

`TOY-INPUT-001` は [ADR-0008](../../docs/adr/0008-content-based-input-observations.md)、`TOY-POSITION-001` は [ADR-0009](../../docs/adr/0009-canonical-python-source-positions.md) を検証する小さい実アプリ対象である。元の未公開ファイルを回収したものではなく、引継ぎ要件から再実装している。

## 設計

[fixtures/expected.json](fixtures/expected.json) に変更後に必要な関数、変更操作、mtime条件、再索引化の要否を手書きで置く。最初の関数 `before` を `after` へ置き換え、空へ切詰め、空から追加し、保存内容だけを欠落／NULLにする。入力のmtimeを変えた事実をOSから読み直して確認する。C++とPythonへ同じ操作を行い、必要な関数・保存内容・診断・CLI再実行件数を確認した後、同じ入力の全体再構築と既存の意味比較器で比較する。

位置対象は `日本語` 関数と `caller` からの呼び出しを持ち、BOMの有無、LF／CRLF、最終改行の有無を組み合わせる。保存位置からバイト列を切り出し、実際に `日本語` を指すことを確認する。呼出辺の種類と方向も独立に確認する。同一入力を二つのPythonグループに登録し、1／2ワーカーで処理した結果を単一グループと比較する。

異常出力ではNULを含む入力と、Python／Customの明示的な所有衝突を作る。終了1だけでなく、採用済みDBの意味保持、問題を除いた後の再試行、クリーン再構築との一致を確認する。空入力へのC++更新は不要な組み込み型が残らないことも観測する。[ADR-0010](../../docs/adr/0010-clearing-unused-builtin-types.md)

## 実行と証跡

リポジトリの `pixi run --locked build` 完了後、固定の試験環境で `python -m pytest -q tests/input_observation` を実行する。実バイナリーがないときはスキップせず失敗する。既存のPython解析用環境も必要である。各プロセスのコマンド・終了コード・標準出力・標準エラーはpytestの一時プロジェクトへ `run-N.log` として残す。

各試験は新しい隔離したプロジェクトと設定ディレクトリを使う。全体の試験結果は今回の実行レポートに収録する。新Python/C++解析器やRust索引器の対応能力は別の題材で確認し、この旧解析器の成功だけで保証しない。
