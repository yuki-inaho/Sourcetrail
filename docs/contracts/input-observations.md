# 入力観測・保存位置の契約

## INPUT-001: 取得済み内容が変更判定の基準になる

同じ入力パスの保存内容と現在内容を共に取得できた場合、正規化された内容が等しいときだけ未変更とする。更新時刻が同一・過去でも差を検出し、内容不変のtouchでは再解析しない。正常な空文字列は取得成功である。保存行の欠落・NULL・SQL問い合わせ失敗、現在ファイルの読込失敗をそれぞれ区別し、索引済み入力では再解析が必要とする。

本文が保存されない非索引依存には時刻による互換判定が残る。削除や列挙は既存のSource Group・更新計画の責務である。全入力の原子的スナップショットはこの契約の範囲外である。[ADR-0008](../adr/0008-content-based-input-observations.md)

## LOCATION-001: 保存内容と位置が同じ座標系に属する

旧Python索引器について、行・列1始まり、UTF-8バイト列、終端込みへ変換する。保存内容のBOMと最終改行を保存し、CRLFはLFへ正規化する。トークン位置から切り出したバイト列が意図した名前と一致することを、文字数の比較とは別に確認する。変換不能な座標や不一致内容を正常な位置として採用しない。[ADR-0009](../adr/0009-canonical-python-source-positions.md)

固定版の旧Pythonライブラリーが省略する空内容の行は、実入力が空・索引済みPythonの所有行が一意・位置行なし、という条件を全て確認した場合だけ作成する。これにより正常な空ファイルも採用後は明示的な取得済み内容を持つ。

## EXECUTION-001: 不正出力は採用しない

プロセス成功件数と出力拒否件数を区別する。全ワーカー終了後、DB／Pythonソース単位で一度変換する。失敗した出力を含む候補は既存の失敗終了経路で破棄し、採用済み索引を保持して終了値1を返す。後続の成功は出力拒否を消さない。SQLite位置更新は一処理内で全て成立するか、savepointで全て戻る。

任意のCustom出力の完全性や一般的なDB公開原子性は、この旧Python出力検査から推論しない。
