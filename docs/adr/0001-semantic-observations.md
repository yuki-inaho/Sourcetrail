# ADR-0001: 観測プロファイルで意味の同等性を定義する

- 状態: 採用
- 日付: 2026-10-30
- 関連契約: `GRAPH-001`, `NAME-001`, `STORAGE-001`, `QUERY-001`
- 関連仕様: [概念](../architecture/domain-model.md)、[保存と問い合わせ](../architecture/storage-and-query.md)

## 背景

Sourcetrail の役割は記号・関係・位置・診断を探索可能にすることである。大きな内部変更や解析器の更新を、単にテスト件数や DB の行数で判定すると、誤った呼び出し先や位置を見逃す。一方、DB のバイト列や ID を完全一致させると、意味を変えない挿入順や ID の付け替えを回帰と誤認する。

`Storage::inject` は実際に要素 ID と位置 ID を保存先で付け替える。`NameHierarchy` は表示名に現れないシグネチャを持ち、Python 後処理は曖昧な関係を記録する。これらを比較の設計に反映する必要がある。[Storage.cpp](../../src/lib/data/storage/Storage.cpp)、[NameHierarchy.cpp](../../src/lib/data/name/NameHierarchy.cpp)、[TaskExecuteCustomCommands.cpp](../../src/lib/data/indexer/TaskExecuteCustomCommands.cpp)

## 決定

比較前に、入力、解析設定、対象言語、エンジン版、対応能力、観測範囲、許容する正規化を固定する。同じプロファイルの観測が一致する場合に限り、その観測範囲で同等と扱う。

| 比較対象 | 保持するもの | 正規化できるもの |
| --- | --- | --- |
| 記号 | 保存された完全な階層・シグネチャ、種別、定義状態 | 保存ごとの数値 ID |
| 関係 | 種別、始点・終点、曖昧性、出現 | 数値 ID、行列挙順 |
| 位置 | ファイル、開始・終了、位置種別、要素との対応 | 宣言したプロジェクトルートの写像 |
| ファイル | 言語、indexed、complete、内容に関する対象観測 | 処理時刻、保存上の数値 ID |
| 診断 | 対象、位置、fatal／indexed 等 | 文言の扱いは比較プロファイルで事前定義 |
| 問い合わせ | 候補、順位、フィルター、経路、選択先等 | 意味に影響しない内部表現だけ |

名前の末尾だけに縮めたり、関係を無向化したり、曖昧性を取り除いたりしない。ルートの正規化は明示したルートだけに適用し、任意の部分文字列の置換で名前や診断の意味を消さない。

比較ツールは、自身の比較対象を明記する。[semantic_graph.py](../../script/verification/semantic_graph.py) のスキーマ 25 の比較結果から、GUI の候補順位や描画の同等性を推論しない。対応していないスキーマや欠落した必須構造は失敗として扱う。

新しい解析器で旧版の誤りを直す場合は、差分を改善として記録し、独立した正しい期待を追加する。旧版が理解できない構文は旧版一致では評価せず、対応能力の追加として評価する。

## 代替案

| 案 | 採用しない理由 |
| --- | --- |
| SQLite の完全なバイト比較 | ID・順序・保存時刻等まで固定してしまう |
| ノード数・辺数だけの比較 | 同数の誤った参照先や失われた位置を検知できない |
| 修飾を除いた表示名だけの比較 | 同名記号やオーバーロードが衝突する |
| 一つの「全言語同等」判定 | 言語固有の意味と解析能力の差を隠す |
| 全プログラムの実行意味の証明 | 本ツールの観測目的と異なり、現行の解析情報だけでは扱えない |

## 影響と検証

比較器自体を、ID／ルートだけが違う同等例と、参照先・シグネチャ・曖昧性・位置・状態を変えた非同等例で検証する。実アプリの索引結果にも適用する。将来の保存形式変更では、各形式から同じ観測へ写すアダプターを用意する。

残る範囲は、[GAP-003、GAP-008、GAP-009](../architecture/evolution-plan.md) として追跡する。有限の例が一致しても全入力の等価性を証明したとは報告しない。
