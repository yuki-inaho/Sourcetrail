# 007 — 外部索引器の人工対象と変更前の失敗基準

記録日: 2026-10-30（Asia/Tokyo）。基準コミット: `78e63759709be5a2f9380f3c4b0f92cc48dfd4ed`。
本バッチは3 source単位を扱う。新しい解析器を接続する前に、[ADR-0004](../../../adr/0004-language-capabilities.md)の実行境界を実装へ接続するため、`GAP-005` を小さい人工対象で再現した。
設計判断は [ADR-0007](../../../adr/0007-external-indexer-outcomes.md)、受入契約は [EXECUTION-001](../../../contracts/external-indexing.md)。

## なぜこの対象を選んだか

既存のC++／Pythonトイは保存グラフの同等性を確認する。一方、外部解析器が起動しない、非ゼロで終了する、といった失敗は解析能力とは別に扱う必要がある。
既存コードでは実行失敗のログを出した後も成功件数を増やし、スケジューラーの完了から通常の索引採用とCLI終了へ進む。その経路を、実際のアプリで観測できる対象にした。

人工索引器は新しい言語を解析せず、宣言した終了値・標準エラー・無出力を返す。自分が実行されたことを別のJSONへ書き、索引DBには書き込まない。
保持する旧索引は実C++解析器で作り、次の索引化ではC++の関数名を変更する。これにより、候補を誤って採用すると旧索引と異なることを、件数だけに頼らず確認できる。

## 注釈単位

### ANN-001 — 手書きの期待値

[expected.json](../../../../tests/external_indexer/fixtures/expected.json) は、起動不可、終了7、stderr付き終了0、無出力終了0、成功失敗が混在する直列・並列の6ケースを定義する。
加えて、直列・並列のそれぞれで「旧索引を作る→失敗する更新→成功する再試行→独立した全体索引化」を確認する。
終了0だけでは意味のある索引を保証できないという既存Custom契約も、0件の観測として明示的に残す。

### ANN-002 — 独立した実行記録

[driver.py](../../../../tests/external_indexer/fixtures/driver.py) は選択された `.toy` 入力へコピーされ、PixiのPythonをshebangにして実行される。
実行記録にはモード、終了値、ソース、cwd、引数、PIDが入る。日本語・空白を含むパスで、Customコマンド `"%{SOURCE_FILE_PATH}"` を使う。
これは既存の引数なしコマンド文字列の引用規則に従うためで、コマンド解析の本番仕様は変更しない。

### ANN-003 — 実アプリを通る観測

[基準取得時の実行器](evidence/baseline-harness.py) は、summaryに記録したSHA-256と一致するソースの保存コピーである。現在の実行器の編集先ではない。
アプリのCLIを起動し、終了後にログ・実行記録・残る一時DB・`schema25-exact-v1` の保存観測を取得する。
既存索引と失敗後の観測を完全比較し、再試行後には旧名が消えて新名が現れ、別ルートの全体索引化と一致することを要求する。

## 変更前の結果

実行コマンド、対象バイナリー、入力設定の訂正履歴は [verification.json](evidence/verification.json)、全観測は [summary.json](evidence/baseline/summary.json) に保存した。
基準実行の終了コードは **1**。新しい期待契約に違反する元実装の結果を、そのまま失敗として記録している。

| ケース | 変更前の実観測 | 新契約との関係 |
| --- | --- | --- |
| 起動不可 | アプリ終了0、成功1/1、人工プログラムの記録なし | 失敗 |
| 人工プログラムが終了7 | 実行記録は終了7、アプリ終了0、成功1/1 | 失敗 |
| stderr付き終了0 | 警告を保持、アプリ終了0、成功1/1 | 維持する既存挙動 |
| 無出力終了0 | アプリ終了0、成功1/1、索引ファイル0件 | プロセス成功だけの互換性観測 |
| 直列で一成功・一失敗 | 両方の実行記録あり、アプリ終了0、成功2/2 | 失敗 |
| 並列で一成功・一失敗 | 両方の実行記録あり、アプリ終了0、成功2/2 | 失敗 |
| 旧索引あり、更新中に失敗 | 両スケジュールで候補が採用され、旧観測と不一致 | 失敗 |

[終了7の原文ログ](evidence/baseline/nonzero-exit/execution.log)には、外部プロセスの非ゼロ終了と、アプリの成功終了が両方残っている。
再試行の成功と全体索引との一致は変更前でも成立する。今回の修正では、失敗を正しく伝えることと旧索引を保持することを、正常系の互換性と分離して判定する。

実行バイナリーのSHA-256は `51b9e74eb9d344ea136b89c17aaf0eb59eaa801f984a1974a94004f1b76889d7`。
[005の成功済み14段階](../005-portable-core-and-verification/evidence/refactored/summary.json)のバイナリーと同じ内容であることも確認した。基準コミットは呼出し側の申告であり、作業ツリーからビルド版を自動推定したとは扱わない。

## 実験手順で訂正した点

最初の試行では変数記法の誤り、次の試行では空白を含む実行パスの引用不足があった。どちらも人工プログラムの実行記録が欠け、検査で拒否された。
本バッチの基準には、記法と引用を直し、起動不可以外の全対象で正しいモードと終了値を確認できた最後の実行だけを使っている。
後から追加した実行器のタイムアウトログ保存・記録内容の厳格化は、保存した基準実行器やそのハッシュへ遡って反映しない。
